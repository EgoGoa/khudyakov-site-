# Блог в подвале: как обновлять

Витрина в подвале сайта читает **один файл** — `content/blog/posts.json`.
Агент (или человек) раз в неделю перезаписывает его, делает коммит — сайт пересобирается.
Код трогать не нужно.

## Формат

- `updated` — дата обновления, `YYYY-MM-DD`.
- `posts` — массив материалов. Порядок не важен: сайт сортирует по `date` (новые первыми).

Поля материала:

| поле | обяз. | описание |
|---|---|---|
| `id` | да | уникальный, латиницей: `case-2026-10-fest` |
| `rubric` | да | `cases` · `trends` · `tools` · `team` |
| `title` | да | заголовок, до ~90 знаков |
| `excerpt` | да | 1–2 предложения, до ~160 знаков |
| `date` | да | `YYYY-MM-DD` |
| `readMin` | нет | минут чтения |
| `url` | нет | ссылка на полный материал (пост в Telegram, страница). Без неё карточка не кликабельна |
| `metrics` | нет | только для `cases`: до 3 пунктов `{label, value, percent 0–100}` |

## Правила

- Только факты, которые можно подтвердить. Цифры кейсов — только согласованные с клиентом. Не выдумывать.
- Карточки с «ДЕМО-ТЕКСТ» в `excerpt` — заглушки, при первом обновлении удалить.
- Показываются: 1 свежий кейс с метриками, до 3 трендов, по 1 инструменту и новости команды.
  Если рубрика пуста, её вкладка скрывается. Если материалов нет совсем, блок не выводится.
- Не больше 12 материалов на рубрику — старые удалять.
