## Проверка вёрстки (правило Егора)

На каждом скрине и при каждой правке UI сам ищи и первым делом называй наложения: текст на текст, текст шире своей карточки/рамки, кнопки и стрелки поверх контента, просвечивающий снизу контент. Сначала перечисли такие наложения, потом остальное. Не жди, пока Егор спросит.

Перед каждым деплоем (push в main или npm run deploy:ru) после правок вёрстки: `npm run build && npm run audit:overlaps`. Скрипт проходит все окна-сцены в размере телефона и падает, если текст лёг на текст или вылез из рамки; снимки сцен — в `_audit/`, их тоже просмотреть глазами (текст поверх рисунков скрипт не ловит).

## Брифы

Брифы. Каждая страница услуги обязана иметь бриф своей категории. Конфиги — `src/features/brief/configs/*`, привязка — `registry.ts` (`serviceBriefMap`; подстраницы раздела наследуют бриф раздела). Ссылки с кнопок ведут на `/brief/<content|sites|smm|ai>`; в общих компонентах — `briefHrefForRoute(pathname)`, голый `/brief` на страницах услуг запрещён. Не меняй привязку, общий компонент Brief и конфиги, если задача прямо не про брифы. После любой правки страниц услуг запускай `npm run check:briefs` (он же в `prebuild`, сборка падает при поломке привязки). Заявки уходят через `/api/lead` (Resend) с типом `brief-<id>`.
